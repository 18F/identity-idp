# RFC 7009 — OAuth 2.0 Token Revocation

RFC 7009 defines the endpoint a client calls to tell the server it no longer needs a token.
Here it lets a service provider end delegated access early: a refresh token ends its whole family,
an access token or SAML assertion ends that one token. The endpoint never confirms whether a token
exists or whose it is. Canonical text: https://www.rfc-editor.org/rfc/rfc7009.txt

## Sections this implementation relies on

- **§2 Token revocation endpoint.** The server validates the client credentials and verifies the
  token was issued to the client making the request before invalidating it; if the token is a
  refresh token and the server supports access-token revocation, it SHOULD also invalidate the
  access tokens based on the same grant; if the token is an access token, the server MAY revoke
  the related refresh token. `OpenidConnectRevokeForm` (`app/forms/openid_connect_revoke_form.rb`):
  `#validate_client` through `DelegatedAccessClientHandling`; `#owned?` requires the token's
  service provider to be the caller (and, for a public client, its binding to equal the proof key);
  `#revoke_refresh_family` ends the family through `TokenExchangeRefreshToken.revoke_family!`
  (`app/models/token_exchange_refresh_token.rb`); `#revoke_access_token` removes one live entry
  (`DelegatedTokenStore.revoke_token`) and marks its issuance record. Companion REF-8; D69, E107.
- **§2.1 Revocation request.** `POST` with `token` REQUIRED and `token_type_hint` OPTIONAL
  (`access_token` or `refresh_token`); if the server cannot locate the token with the hint it MUST
  extend its search across all supported token types. `#validate_token_present` requires `token`
  (`invalid_request`); `#revoke!` orders the two lookups by the hint and tries both.
- **§2.2 Revocation response.** HTTP 200 whether the token was revoked or was invalid; invalid tokens
  do not cause an error because the client could not act on one. `#http_status` is `:ok` and
  `#response` is `{}` for every authenticated outcome, including unknown, foreign, already revoked
  and differently bound tokens (companion §7.3 "As built").
- **§2.2.1 Error response.** RFC 6749 §5.2 codes, plus `unsupported_token_type`; `invalid_client` may
  be 401. `#http_status` returns 401 for `invalid_client` and 400 for `invalid_request` and
  `invalid_dpop_proof` (RFC 9449 §5).
- **§2.3 Cross-origin support.** The endpoint MAY support CORS for browser clients. The route carries
  the token endpoint's `Rack::Cors` rule so the public-client service provider can revoke from the
  browser (D59; `config/application.rb`).
- **§5 Security considerations.** Unauthenticated callers must not be able to revoke others'
  tokens; the endpoint must not become an oracle. Ownership is checked before any action and every
  authenticated answer is identical.

## Deliberate choices and deviations

- **A public client authenticates with a DPoP proof carrying `ath` over the presented token**
  (`#validate_public_client_proof`), since it has no secret; a token bound to a different key is
  not acted on (REF-8 with EXC-17).
- **Refresh token ends the family; access token ends itself only.** §2 makes the cascade from an
  access token to the refresh token optional; here it is not done, and the same holds for a SAML
  assertion revoked by `ID` or encoded assertion (D69, E107).
- **The client's own sign-in access token is accepted and not acted on**: ending the sign-in is
  the logout flow's job; this endpoint ends delegated access only.
- **SAML assertions are revoked by `Assertion/@ID` or by the encoded plaintext assertion**
  (`DelegatedSamlAssertion.reference_for`, `app/services/delegated_saml_assertion.rb`); accepting
  the bare ID is a Login.gov extension flagged for review (E14, SAML-12).
- **`unsupported_token_type` is never returned**: both hint values are supported and a wrong hint
  only changes lookup order.
- **The revocation reason `client_revoked`** is recorded and reported to the agency through the
  Attempts API (`DelegatedAccessEvents.access_revoked` inside `revoke_family!`).

## Questions this digest answers

- What does a revoked, unknown or foreign token return? `200 {}` once the caller authenticated.
- Does revoking an access token end the refresh token? No; revoke the refresh token to end the family.
- Which hint should I send? Either; a wrong hint is not an error (§2.1).
- Can an encrypted SAML assertion be the `token`? No; its ID is inside the ciphertext. Use the ID or the refresh token (SAML-12).
- When is the answer not 200? 401 `invalid_client`, 400 `invalid_request` (no `token`) or 400 `invalid_dpop_proof`.
- Can a browser client call it? Yes, with `client_id` and a DPoP proof; CORS is enabled (D59).
