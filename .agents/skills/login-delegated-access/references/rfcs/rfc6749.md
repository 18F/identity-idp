# RFC 6749 — The OAuth 2.0 Authorization Framework

RFC 6749 is the base protocol every delegated-access endpoint builds on: the token endpoint, the
grant-type dispatch, client authentication for confidential and public clients, the shape of a
token response and of an error response, and the refresh-token grant. The delegated-access grants
(RFC 8693 token exchange, the `refresh_token` grant) are served at the existing token endpoint and
answer with RFC 6749 §5.1 and §5.2 objects. Canonical text: https://www.rfc-editor.org/rfc/rfc6749.txt

## Sections this implementation relies on

- **§2.3, §3.2.1 Client authentication at the token endpoint.** A confidential client MUST
  authenticate; a public client identifies itself with `client_id`. How the code honors it:
  `DelegatedAccessClientHandling#validate_client` (`app/forms/concerns/delegated_access_client_handling.rb`)
  authenticates a confidential service provider by `private_key_jwt` (RFC 7523) and identifies a
  public one by `client_id`, refusing the other kind's credential (`client_type_mismatch`). Companion
  EXC-2 as amended (§5.5), decisions D19–D22 of the 2026-10-09 baseline change.
- **§3.3 Access token scope.** Scope is a space-delimited list of opaque strings. The issued
  `scope` is always the application's registered delegation scope
  (`OpenidConnectTokenExchangeForm#create_issuance_record!`, `app/forms/openid_connect_token_exchange_form.rb`);
  a `scope` parameter on the exchange is ignored (D72, E111) and on refresh must equal the family's
  (`OpenidConnectRefreshTokenForm#validate_refresh_token`, `invalid_scope`; REF-3).
- **§4.1.2.1 Authorization error response.** An unknown or unauthorized scope value is
  `invalid_scope`, not `invalid_request`. `OpenidConnectAuthorizeForm#error_redirect_uri`
  (`app/forms/openid_connect_authorize_form.rb`) picks `invalid_scope` for delegation-scope errors (D14).
- **§4.5 Extension grants.** An extension grant is selected by an absolute URI in `grant_type`.
  `OpenidConnect::TokenController#build_form` (`app/controllers/openid_connect/token_controller.rb`)
  dispatches `urn:ietf:params:oauth:grant-type:token-exchange` to `OpenidConnectTokenExchangeForm`
  while `token_exchange_enabled` is on (EXC-1, EXC-10).
- **§5.1 Successful response.** `access_token` and `token_type` are REQUIRED, `expires_in`
  RECOMMENDED, `refresh_token` and `scope` OPTIONAL; additional parameters are permitted.
  `OpenidConnectTokenExchangeForm#response` and `OpenidConnectRefreshTokenForm#response` return
  these plus the non-standard `refresh_token_expires_in` and, for a SAML family, `session_live: false`
  (EXC-16, E6, E112; D73). `OpenidConnectTokenForm#granted_scope` (`app/forms/openid_connect_token_form.rb`)
  adds `scope` to the authorization-code response only when delegation scopes were requested.
- **§5.2 Error response.** A JSON object with `error` from the fixed set (`invalid_request`,
  `invalid_client`, `invalid_grant`, `unauthorized_client`, `unsupported_grant_type`,
  `invalid_scope`), optional `error_description`, HTTP 400; `invalid_client` MAY be 401.
  `DelegatedAccessClientHandling#fail_with` records the first code and `#error_response` builds
  the object (EXC-11). `OpenidConnectUnsupportedGrantForm` (`app/forms/openid_connect_unsupported_grant_form.rb`)
  answers `unsupported_grant_type` for any grant the endpoint does not serve (D71, E110).
  `OpenidConnectRevokeForm#http_status` returns 401 for `invalid_client` (`app/forms/openid_connect_revoke_form.rb`).
- **§6 Refreshing an access token.** `grant_type=refresh_token`, `refresh_token` REQUIRED,
  `scope` OPTIONAL and never wider than the original grant; the server MUST authenticate a
  confidential client and MUST validate the refresh token; it MAY issue a new refresh token, and
  the client MUST then discard the old one. `OpenidConnectRefreshTokenForm` (`app/forms/openid_connect_refresh_token_form.rb`)
  does all of this and always rotates (`#rotate_locked!`); `TokenExchangeRefreshToken`
  (`app/models/token_exchange_refresh_token.rb`) is the rotating, digest-only row (REF-2, REF-3, REF-4, REF-7).
- **§10.3, §10.4 Token confidentiality and refresh-token binding.** Tokens are confidential in
  storage; refresh tokens are bound to the client they were issued to. Only digests are stored
  (`DelegatedAccess::OpaqueToken.digest`, `DelegatedTokenStore`, `TokenExchangeRefreshToken.digest`);
  a refresh token presented by another client is `invalid_grant` with the same wording as an
  unknown token (`#validate_refresh_token`; E62).

## Deliberate choices and deviations

- **Error codes the RFC does not define.** `invalid_target` (RFC 8693), `invalid_dpop_proof`
  (RFC 9449) and `consent_required` (OpenID Connect Core §3.1.2.6, borrowed for the exchange) are
  returned in the §5.2 object. Rationale: D31 (`consent_required` tells the service provider which
  scope to request), companion §5 "Errors".
- **Every token-endpoint error is HTTP 400**, including `invalid_client` (the endpoint's existing
  convention, EXC-10, EXC-11); only the revocation and introspection endpoints use 401.
- **No `id_token` on the exchange or refresh.** A delegated token is not a sign-in credential at
  the agency (EXC-5).
- **PKCE is refused on the delegated grants** (`#validate_code_verifier_absent`): it is not a client
  credential (EXC-2).
- **Scope is never narrowed** on the exchange (D72): one scope per application leaves nothing to narrow.

## Questions this digest answers

- Why is `grant_type=foo` now `unsupported_grant_type` instead of a validation message? §5.2 names the code; D71 adopted it (error path only).
- Can a public client call the token endpoint without a secret? Yes: §3.2.1 lets it send `client_id`; it is authenticated by its DPoP proof instead (RFC 9449).
- Which error does a wrong client credential produce? `invalid_client`, always, including a client not approved for delegation (EXC-15).
- Is `refresh_token_expires_in` standard? No; §5.1 permits additional members (E6).
- Must the client discard the old refresh token? Yes (§6); presenting it again is reuse and revokes the family (RFC 9700).
- Where is `scope` validated on refresh? `OpenidConnectRefreshTokenForm#validate_refresh_token`; anything but the family's exact scope is `invalid_scope`.
