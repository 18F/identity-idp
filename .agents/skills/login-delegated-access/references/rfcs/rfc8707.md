# RFC 8707 — Resource Indicators for OAuth 2.0

RFC 8707 adds the `resource` request parameter so a client can say which protected resource a
token is for, and so the server can audience-restrict the token to it. In this repository
`resource` names the one agency API a delegated token is issued for; its value is the registered
identifier of a `TokenExchangeResourceServer`, becomes the token's `aud`, and selects the
token format. Canonical text: https://www.rfc-editor.org/rfc/rfc8707.txt

## Sections this implementation relies on

- **§2 Resource parameter.** `resource` is an absolute URI (RFC 3986) that MUST NOT include a
  fragment and SHOULD NOT include a query; it MAY appear more than once; the server SHOULD
  audience-restrict issued tokens to the indicated resource. `OpenidConnectTokenExchangeForm#validate_resource`
  (`app/forms/openid_connect_token_exchange_form.rb`) looks the value up by exact match on
  `TokenExchangeResourceServer#identifier` (`app/models/token_exchange_resource_server.rb`), so
  only a registered identifier is ever accepted, and the issuance record's `aud` is that identifier
  (`TokenExchangeToken#live_attributes`, `app/models/token_exchange_token.rb`). Companion EXC-1, EXC-4.
- **§2 `invalid_target`.** If the server fails to parse the value or does not consider the resource
  acceptable, it should reject the request with `invalid_target`. `#validate_resource` answers
  `invalid_target` with one wording for an unknown identifier, an unusable API (API, application or
  agency inactive) and an application that does not accept this service provider (EXC-3; D31, E26).
- **§2.2 Access token request.** The parameter is used at the token endpoint to indicate the target
  service; RFC 8693 §2.1 adopts it for the exchange. `OpenidConnect::TokenController#token_params`
  (`app/controllers/openid_connect/token_controller.rb`) permits `resource` as a scalar and as an
  array so a repeated parameter is seen and counted.
- **§3 Security considerations.** Audience restriction prevents a token issued for one resource
  from being used at another. Introspection answers `active: false` to any resource server other
  than the token's audience (`OpenidConnectIntrospectForm#caller_entitled?`), and a SAML
  assertion's `Audience` is the resource identifier and nothing else (`DelegatedSamlAssertion#builder`).

## Deliberate choices and deviations

- **Exactly one value.** RFC 8707 allows several; a request with two or more fails with
  `invalid_request` (`#validate_request_shape`, `multiple_resources`). Rationale: one token, one
  audience (D30; EXC-1 confirmed in §5.6).
- **`resource` is required on the exchange** although RFC 8693 §2.1 makes it OPTIONAL: with no
  `audience` parameter read, there is no other way to name the API (`resource_missing`).
- **`resource` is refused on refresh** with `invalid_request` rather than ignored: the audience is
  fixed by the family; a service provider that wants another API exchanges again
  (`OpenidConnectRefreshTokenForm#validate_request_shape`, REF-11).
- **The resource decides the format.** The registered `token_format` of the resource named here is
  what the exchange issues (D70), so `resource` carries more than audience.
- **No URI normalization.** The lookup is an exact string match against the registry, so partners
  must send the identifier exactly as registered (companion §3.3 onboarding YAML).
- **Lookup after authentication.** The resource is checked only after the client, subject token,
  proof and session checks, so an unauthenticated caller learns nothing about the registry.

## Questions this digest answers

- What goes in `resource`? The agency API's registered identifier, verbatim.
- Can one exchange cover two APIs? No (`invalid_request`); exchange twice.
- Why do "unknown" and "inactive" look the same? One `invalid_target` wording so the endpoint is not a registry oracle.
- Does `resource` work on `grant_type=refresh_token`? No; `invalid_request` (REF-11).
- Where does `aud` in introspection come from? The resource identifier stored on the live entry at issuance.
- Is `audience` (RFC 8693) supported instead? No; only `resource` is read.
