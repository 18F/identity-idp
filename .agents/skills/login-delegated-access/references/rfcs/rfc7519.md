# RFC 7519 — JSON Web Token (JWT)

RFC 7519 defines the compact, signed claims set that two of this implementation's credentials are
built on: the RFC 7523 client assertion and the RFC 9449 DPoP proof. It names the registered
claims (`iss`, `sub`, `aud`, `exp`, `nbf`, `iat`, `jti`), the `typ` header and the validation
steps. Delegated tokens themselves are never JWTs (D29, EXC-20). Canonical text: https://www.rfc-editor.org/rfc/rfc7519.txt

## Sections this implementation relies on

- **§4.1.1 `iss`, §4.1.2 `sub`.** Issuer and subject of the JWT. `ResourceServerAuthenticator#unverified_issuer`
  (`app/services/resource_server_authenticator.rb`) requires `iss` to be a string equal to `sub`
  and uses it to select the record whose keys verify the assertion (RFC 7523 §3 items 1 and 2).
- **§4.1.3 `aud`.** A string or an array of strings; a recipient not in `aud` MUST reject the JWT.
  `ResourceServerAuthenticator#audience_matches?` wraps the value with `Array.wrap` and requires one
  entry equal to the endpoint URL; `OpenidConnectTokenForm#validate_aud_claim`
  (`app/forms/openid_connect_token_form.rb`) does the same for the authorization-code grant.
- **§4.1.4 `exp`, §4.1.6 `iat`.** NumericDate values; a JWT MUST NOT be accepted after `exp`, with
  a small leeway permitted. The authenticator requires `exp` (`REQUIRED_CLAIMS`), caps `exp - iat`
  at 300 seconds (`#lifetime_acceptable?`) and refuses a future `iat` beyond ten seconds
  (`#issued_at_acceptable?`). `DpopProofVerifier#issued_at_acceptable?` (`app/services/dpop_proof_verifier.rb`)
  accepts `iat` within `dpop_proof_max_age_seconds` either side of now and does not use `exp`.
- **§4.1.7 `jti`.** A unique identifier that can be used to prevent replay. Both credentials require
  it and record it once through `ReplayGuard.first_use?` (`app/services/replay_guard.rb`) under the
  presenter's identity; see the RFC 7523 and RFC 9449 digests.
- **§5.1 `typ` header.** Declares the media type of the JWT. The DPoP proof MUST carry
  `typ: dpop+jwt` (RFC 9449 §4.2), checked by `DpopProofVerifier#call` (`PROOF_TYPE`); explicit
  typing is RFC 8725 §3.11.
- **§7.2 Validating a JWT.** Parse the header, determine the algorithm and key, verify the signature,
  then validate the claims; reject on any failure. Both verifiers decode the token unverified only
  to learn which key to use (`#decode_unverified`, `#unverified_issuer`), then verify with a pinned
  algorithm (`JWT.decode(..., algorithm:)`) and compare the verified payload to the one read first.
- **§2 NumericDate.** Seconds since the epoch. `DpopProofVerifier#issued_at_acceptable?` requires an
  Integer `iat`; the authenticator accepts Numeric `exp` and `iat`.

## Deliberate choices and deviations

- **Delegated tokens are opaque references, not JWTs** (D29; companion §0.2 on RFC 9068): an agency
  must introspect, and nothing about the person leaks to the service provider carrying the token.
- **`exp` required even though RFC 7519 makes every claim optional**, following RFC 7523 §3 and
  OpenID Connect Core §9 for the client assertion; the DPoP proof uses `iat` only, as RFC 9449 does.
- **The library's `iat`/`exp` checks are turned off** (`verify_iat: false`, `verify_expiration:
  false` for proofs) and done by hand, so the windows are this implementation's, not the library's.
- **Payload equality check after signature verification** in `DpopProofVerifier#call` guards
  against a library returning a different payload than the one read unverified.
- **`nbf` is not used** by either credential.

## Questions this digest answers

- Is a delegated access token a JWT? No; it is 32 random bytes base64url (`DelegatedAccess::OpaqueToken`).
- Which claims must a client assertion carry? `iss`, `sub`, `aud`, `exp`, `jti` (`iat` optional).
- Which claims must a DPoP proof carry? `jti`, `htm`, `htu`, `iat` (`ath` when a token is presented).
- How much clock skew is tolerated? Ten seconds on client assertions; 300 seconds either way on proofs.
- Why decode without verifying first? Only to learn `iss`/`sub` or `jwk`; nothing else is trusted from that read.
- May `aud` be an array? Yes; one element must equal the endpoint URL.
